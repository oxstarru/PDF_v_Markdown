# Спецификация утилиты «PDF в Markdown»

---

## Паспорт

- **Номер:** № 10 (сквозной по реестру утилит)
- **Название:** PDF в Markdown
- **Версия:** 2.0
- **Категория:** разные
- **Автор идеи:** Оксана Старкова
- **Реализация (вайб-код):** ИИ10 (версии 0.1–0.4), ИИ10-2 (0.5–2.0)
- **Дата создания / доработок:** 03.08.2026 (создание) · 04.08.2026 (картинки и галерея, 1.0) · 10.08.2026 (доработка, 2.0)
- **Тип:** single-file HTML
- **Приватность:** полностью локально, обращений в сеть нет

## Назначение

Преобразует PDF с текстовым слоем в Markdown-заметку для базы знаний. Восстанавливает структуру документа (заголовки, списки, абзацы, простые таблицы) и отдельно извлекает встроенные растровые изображения, подставляя на их место ссылки в тексте. Задача — быстро переводить учебные и рабочие материалы в формат базы знаний, а не добиваться полиграфической точности.

## Вход и выход

- **Вход:** один файл `.pdf` (перетаскиванием или через диалог выбора).
- **Выход:**
  - Markdown в поле предпросмотра — можно скопировать в буфер;
  - файл `Название.md`;
  - архив `Название.zip` — одна папка, внутри `.md` и PNG-файлы картинок (ссылки в тексте — по имени файла).

## Функциональность

**Разбор текста.** Элементы текстового слоя группируются в строки по координате Y, дальше:

- заголовки определяются по кеглю относительно медианного размера тела (`≥1,6` → `##`, `≥1,22` или жирный `≥1,08` → `###`), многострочные заголовки склеиваются;
- маркированные списки ловятся по широкому набору символов, включая частную область Unicode (`U+E000–U+F8FF`) — оттуда берут маркеры многие презентации; продолжение пункта на следующей строке приклеивается к нему; соседние пункты не разделяются пустой строкой;
- перенесённые строки абзаца склеиваются по вертикальному зазору;
- таблицы: строка режется на ячейки по горизонтальным разрывам (порог `max(размер×2, 16)`), полоса из двух и более согласованных строк собирается в Markdown-таблицу; число колонок берётся по моде.

**Извлечение картинок.** Через `page.getOperatorList()` с отслеживанием матрицы преобразования и стека `save`/`restore`, включая `paintFormXObject`. Обрабатываются три способа размещения:

1. прямой `paintImageXObject`;
2. `paintInlineImageXObject`;
3. **заливка фигуры tiling-паттерном**, внутри операторов которого лежит изображение — так экспортируют Google Slides и Canva; координаты берутся из bbox заливаемого пути.

Объекты забираются из `page.objs`, а переиспользуемые между страницами (префикс `g_`) — из `page.commonObjs`. Пиксели раскладываются в canvas: поддержаны `kind` 1 (1 бит на пиксель, с учётом байтового выравнивания строк), 2 (RGB) и 3 (RGBA), а также вариант `bitmap`, когда pdf.js отдаёт готовый ImageBitmap.

**Фильтры и дедупликация.**

- пропуск, если натуральный размер меньше `MIN_IMG_PX` = 50 px по любой стороне;
- пропуск, если картинка нарисована на странице мельче `MIN_DRAWN_PT` = 24 pt по любой стороне;
- дедупликация по хэшу пикселей (FNV-1a по прореженной выборке из `getImageData` плюс размеры) — повторяющийся логотип или фон отдаётся один раз.

**Размещение в тексте.** Картинки страницы сортируются по Y и вставляются в поток маркерами `@@IMG:id@@` перед тем блоком текста, который расположен ниже картинки. Итоговый Markdown собирается из шаблона с маркерами, поэтому снятие галочки в галерее мгновенно убирает и файл, и ссылку на него.

**Интерфейс.**

- карточка обрабатываемого файла: имя, размер, число страниц; имя файла также в строке статуса на всех этапах;
- кнопки «Копировать текст», «Скачать .md» — всегда; «Показать картинки (N)» — если картинки найдены; «Скачать архив» — если есть выбранные картинки или отрендеренные страницы;
- галерея по кнопке: превью, чекбокс на каждой, «выделить все / снять все»;
- галочка «Приложить страницы картинками» — независимый режим: каждая страница рендерится в PNG (`scale = 2`), в текст добавляются заголовки «## Страница N»; при переключении файл прогоняется заново;
- итоговый статус: страниц, картинок, повторов пропущено, мелких пропущено, страниц без текста.

## Технические детали

- **Стек:** pdf.js 3.11.174 (библиотека и воркер; воркер вшит в base64 и поднимается через Blob URL), JSZip 3.10.1. Всё внутри HTML, ничего с CDN.
- **Хранение данных:** нет. Результат живёт в памяти вкладки; для превью используются Blob URL, они освобождаются при очистке и при загрузке нового файла.
- **Обращения в сеть:** отсутствуют.
- **Браузеры:** любой современный (нужны `canvas.toBlob`, Blob URL, async/await).
- **Ограничения:**
  - PDF без текстового слоя (сканы) не распознаётся — по решению от 03.08.2026 OCR в утилиту не добавляется, такие файлы идут в чат;
  - векторная графика (схемы из линий и фигур) отдельным файлом не извлекается;
  - сложные таблицы с объединёнными ячейками и многоколоночная вёрстка передаются упрощённо;
  - большие документы обрабатываются ощутимое время: `getOperatorList` вызывается на каждой странице.

## Оформление

Соответствует «Стандарту оформления утилит»: палитра `--accent #B85540`, только системные шрифты, серифный заголовок, «№ 10» моноширинным в правом верхнем углу, двухстрочный футер с версией и обеими ссылками (`target="_blank" rel="noopener"`), иконка-искра вшита в base64 (`.ico`, 4 размера: 16/32/48/64), версия в имени файла через подчёркивание (`PDF_v_Markdown_v2_0.html`). Отклонений нет.

## История версий

> Накопительный раздел. Новая финальная версия добавляется сверху; прежние записи не переписываются. В историю попадают только финальные версии — правки промежуточных сборок свёрнуты в запись той версии, которой они завершились.

### Версия 2.0 (10.08.2026, ИИ10-2)

**Изменено**

- Соседние пункты списка соединяются одним переводом строки вместо пустой строки: раньше список получался разреженным. Находка перенесена из утилиты № 8.
- Имя файла приведено к стандарту оформления v4: подчёркивание вместо точки (`v2_0`, а не `v2.0`). Стандарт обновился 05.08.2026, уже после сборки 1.0.

**Исправлено**

- Освобождение адреса блоба при скачивании — с задержкой: мгновенное освобождение в Firefox и Safari может прервать сохранение больших архивов.

**Технические примечания**

- Склейка блоков вынесена в функцию `joinBlocks(out)`: соседние элементы списка определяются по последней строке предыдущего блока и первой строке следующего.

### Версия 1.0 (04.08.2026, ИИ10, ИИ10-2)

Первая версия. Функциональность описана выше.

*Путь до неё: сборка 0.4 (03.08.2026, ИИ10) — базовый разбор текстового слоя, рендер страниц в PNG по галочке, сборка архива. Сборка 0.5 (04.08.2026, ИИ10-2) — извлечение встроенных растровых картинок с определением места на странице, карточка файла, галерея с чекбоксами, фильтр мелких изображений, дедупликация повторов, чтение переиспользуемых объектов из `commonObjs`. Сборка 0.6 — разбор картинок, нарисованных заливкой tiling-паттерном.*

**Главная находка на пути к первой версии — важно для будущих доработок:**

До сборки 0.6 утилита не видела **ни одной** картинки в презентациях из Google Slides и Canva и честно писала «картинок нет». Причина: там картинка размещается не прямым оператором рисования, а заливкой прямоугольника узором-паттерном, внутри которого лежит изображение. На тестовом файле «Вебинар 10, Практика 6» (41 страница) после правки извлечено 17 картинок: фото преподавателя, схема основных понятий, формулы, оба графика MSE, слайд рефлексии; фон разделителей отдан один раз вместо семи, две декоративные точки 100×100 отсеяны.

*Урок: первый тест был собран самим ИИ и оказался слишком удобным — картинки в нём лежали обычным способом, и проверка прошла зелёной там, где было сломано. Настоящий файл Оксаны вскрыл то, чего синтетика не показала. **Проверять на реальных документах.***
